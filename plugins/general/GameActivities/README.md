# GameActivities 游戏活动

版本 0.1.0，要求 Host 0.17.2、Plugin API 2.2、Frontend API 1.7。启用后提供一张独立活动卡；默认没有订阅，在“活动设置”保存八款游戏的顺序与进度。无需安装对应专项插件。蔚蓝档案支持 cn/jp/global，异环支持 cn/global，其余六款固定 default；显示语言不改变内容进度。

前端使用铺满封面的 Carousel，概览文字位于左下角，底部横线和左右翻页按钮可点击。右上角透明 Emoji 按钮打开“活动设置”；刷新入口位于设置内，刷新只使用已保存的订阅，不保存草稿。轮播频率默认30秒，可保存10–120秒的整数或-1（关闭自动轮播）。悬停、焦点、弹窗、后台和减少动态偏好暂停自动轮播。点击图片区域进入详情，也可聚焦后按Enter/空格打开。详情按卡池与活动分区，再按状态分组；已结束默认折叠。每个活动独立显示时间摘要、介绍和官方链接，长文可展开，来源问题分条显示。

活动设置与页面布局编辑使用同一宽度的弹窗，游戏订阅标题位于连续分隔行卡片外。开关控制订阅；已开启游戏通过公共拖拽把手排序，也支持把手聚焦后的上下方向键。蔚蓝档案与异环的内容进度使用公共选择框，位于对应行的开关左侧。轮播频率独立放在游戏订阅卡片下方，公共数字框在标签下方占满一行。选择、进度和频率均为独立草稿，保存后才生效，取消不写入。字段说明通过悬停或聚焦控件的公共提示气泡显示。

轮播直接显示SRA JSON顶层的version概览：versionName、cover及startTime/endTime；不会从activities中选择单条活动替代概览。只为正式点分版本号显示徽章，蔚蓝档案、星塔旅人的月份占位号不显示版本徽章。详情保留activities中的全部条目，包括网页活动，并可显示官方补充内容。单条活动的玩法、兑换时间与概览结束时间分别保存，无可靠时基时保留原值并停用精确倒计时；异环global不由国内日期推算。

未知开始时间按已开始处理，详情显示“已开始”；原始开始证据继续保存，不生成假定的UTC时间。可靠开始时间在未来时仍显示即将开始，可靠玩法截止已到时显示已结束。未知结束时间显示待核验，不生成倒计时，排序置于有明确截止的进行中活动之后。

## 源码维护

业务规则直接维护在C#、Vue和TypeScript源码中，无业务代码生成器或外部脚本依赖。`frontend/src/ActivityCarousel.vue`只负责轮播交互；`ActivityDetails.vue`管详情分区，`ActivityEventCard.vue`管单条活动，`ActivityDescription.vue`与`formatting.ts`管纯文本展示，`ActivitySettings.vue`管设置草稿。`main.ts`激活时创建一次数据与图片会话，不等待Dashboard挂载；`useActivityState.ts`并行读取并逐个发布游戏快照，`useCoverAssets.ts`并行读取封面且每张就绪即显示，停用时取消请求并释放ObjectURL。`activityPolicy.ts`的状态、排序规则对应后端`src/Policy/ActivityPolicy.cs`。

后端由 `ActivityCoordinator` 协调设置事务、刷新与缓存，`ActivityWebApi` 显式登记六个端点；SRA 和官方公告适配器分别位于 `Providers`，归一化与剧情归属位于 `Normalization`，受限图片缓存位于 `Cache`。官方 HTML 转为纯文本时保留段落、换行及条目，不执行其中代码。`web/` 是 Vite 的发布构建输出，应修改 `frontend/src/` 后重建，不能直接编辑压缩 bundle。

## 来源与限制

SRA adapter固定十一份公开JSON。来源后缀表达生产者内容语言；SRA生产者SHA `18048aff9c2c518db112d1d69e23246164a66bc4`的默认规则和BA时间转换使用Asia/Shanghai，消费端不再次调整时区或结束秒。异环global的无偏移SRA日期采用UTC+8默认值。顶层cover属于概览，不分配给没有独立封面的活动。旧last-good启动时从已缓存原响应重建概览，并复用现有资产清单；旧6秒设置读取为30秒，保存前不改写用户文件。启用即为已保存订阅排队更新；无订阅时不请求来源。图片失败沿用对应活动或同内容期概览的旧资产，随下一次刷新重试，缺图不会在分钟调度中反复请求。

官方读取器`Providers/Official/OfficialSourceReader.cs`为各站点分别维护固定入口：BA国服/日服新闻API与Nexon全球社区公告，米哈游三款游戏官网内容API，终末地新闻服务，星塔新闻JSON，鸣潮G152官网主页目录，以及异环国内/全球静态公告。列表与详情核对来源身份，HTML仅转为纯文本，原API地址、官方详情地址、原语言和实际存在的发布时间分别保留。缺列表、身份不符和结构变化明确报错并保留last-good。鸣潮主页目录与文章目录可能独立更新，采用官网实际展示的主页目录。

`OfficialEventParser.cs`按活动名称、公告段落及开启批次关联同一实体，`OfficialTimeParser`分别读取玩法和奖励兑换时间。BA日服/全球服的已核对译名映射只用于对应复刻活动与开启批次。官方截止优先，聚合原时间留在字段证据中，冲突单独诊断；未注明偏移的日历日期采用下述默认规则，无法确定日期的字段保留原文并停用精确倒计时。删除线时间不参与解析。星塔读取每条新闻的结构化详情，主线纪念活动的玩法、商店时间分别保存。

`OfficialGachaParser.cs`拆分角色、武器/光锥/弧盘、复刻、必得随机招募和其他抽取活动；直接自选与给现有池增加免费次数不另造卡池。星铁角色与光锥保留各自时间，星际潮玩与已有同版本条目合并；终末地按寻访次数结束的申领保留计数条件。官方字段或适用的公告整体时基声明优先；没有显式偏移的官方日期按内容进度默认计算：BA日服/国际服UTC+9，其余UTC+8。默认值记录为source-default/reported，来源说明与详情明确标注默认时区，不当作官方声明；BA国际服明确UTC的公告仍按UTC计算。年份取官方发布时间、日期路径或原文明确年份；没有年份、仅日期、实际维护结束或计数条件的字段保持unknown。原神读取cn_gf01官方祈愿目录并逐条校验详情与类型；常驻祈愿不采用配置文件到期时间作截止。

`OfficialGachaDirectory.cs`核对当前进度综合公告中的全部列举项与独立卡池公告，缺少名称、类别、批次或详情时保持partial。BA国服核对维护公告、预加载批次及必得券使用期限，全球服核对Patch Notes的每个招募名称及UTC截止，日服核对明确募集人数和当前活动批次；星塔核对全部列举的旅人/秘纹招募，终末地核对全部寻访/申领，异环核对角色、弧盘与盲盒。星铁、绝区零核对同版本更新说明及已公布各期的全部角色和武器池，星铁另核对当期幻宠抽取；未公布后续期次不冒充已覆盖。每项complete均附来源与覆盖口径，卡池目录完整与时间字段核验独立。部分官方日程仅在图片或游戏内，完整来源资格仍须十一组合实际核验；公开列表、图片解码、缓存或受控测试通过不能代替完整资格。

`OfficialWikiCatalog.cs`通过公开只读POST读取鸣潮官方社区WIKI首页结构化目录，逐项保留当前角色与武器活动唤取，包括复刻池。两类目录都须与官网当前版本的新池名称交叉核对；同一新池沿用官网公告身份，避免重复。WIKI由社区编辑维护，来源说明保留这一属性；未声明时区的dateRange采用UTC+8默认值，不以官网页面按客户端时区计算的倒计时作为时区证据。新池可打开对应官网版本公告，只有角色/武器图鉴链接的复刻池明确缺少精确详情；目录覆盖限当前展示期，不推断未公布后续池或维护实际完成时刻。

缓存按game/progression/contentLocale/provider/parserVersion隔离，读取端点不触发外网。后台单操作合并，各游戏并行刷新，共享HTTP最多4个并发；文字先发布，单张图片写入后立即更新快照，慢游戏不阻塞其他游戏。逐图发布保留已有官方字段，新公告从原响应重新合并，避免旧公告挡住更正。`EventIdentityResolver`只在同进度、同类别、重叠批次且有同一精确公告或同名同内容期证据时保留身份，别名随快照持久化；独立复刻与歧义候选不自动合并。正式版本回滚在原响应落盘前拒绝。资产清单写入串行化，总图片限额128MiB，按全部组合引用保护资产并回收未引用内容。聚合TTL6h、官方TTL12h，分钟调度检查临界点，手动刷新每组合60秒限频；聚合或官方失败均保留last-good并按1/5/30/120分钟退避，遵守更晚的Retry-After，检查时刻随快照保存。临界点的前后两次检查与TTL合并，标记持久化，重启不重放，离开窗口的历史临界点不补发。HTTP单请求15秒、响应4MiB、图片8MiB、快照512KiB/250活动，只接受固定CDN且MIME/签名一致的栅格图片。

`ActivityWithdrawals`在独立的进度缓存中保存明确撤回：Nexon返回同社区、版面和公告ID的`isDelete=true`，或支持的取消公告标题并在正文链接到已知官方公告。Nexon也复查缓存中的已知公告，不能仅凭首页遗漏判断撤回。404、列表缺项、一般维护和含糊取消文字均保留last-good。撤回只排除精确关联实体及该公告单独生成的卡池；有重叠批次证据的旧聚合别名一起排除，独立复刻和不同精确公告不受影响。综合版本公告撤回时，仅清除依赖它的字段与目录资格，保留聚合条目，原始时间降为待核验，不删除整版本。撤回记录先于合并快照持久化，重启重建及逐图发布都会应用；旧公告不能自动恢复已撤回条目。没有原公告关联的取消消息保留待核验。撤回上限128份公告、250份实体身份，超限报错保留已有记录，不自动遗忘撤回；公开诊断展示最近8份，完整记录继续参与过滤。停用先取消生命周期，再等待存储与刷新退出，阻塞写入也可接收取消。

聚合响应的ETag和Last-Modified随原响应保存；优先发送If-None-Match，没有ETag时发送If-Modified-Since，304只复用对应组合的原响应。90秒组合预算覆盖图片、官方补充和快照提交，单请求仍为15秒。JSON读取和官方文本遍历接受生命周期取消，取消时不发布不完整文本。缓存命中也更新并保存最后引用时间；128MiB配额按最后引用时间回收未被任何组合引用的实际资产，清单遗漏的孤立资产也可回收，全部仍有引用时保留旧图。Windows文件替换被拒绝或磁盘写入失败时保留last-good并显示stale；连失败状态也无法落盘时，在当前内存快照中保留失败诊断，恢复存储后可再次刷新。

## 插件 API

全部使用 General：GET state（Host UTC 时基、revision、设置和摘要）；GET feed（gameId/progressionId/contentLocale）；PUT settings（expectedRevision、完整 settings，冲突409）；POST refresh（`{ "selected": true }`，返回202 operationId）；GET refresh-status（operationId，30分钟有效）；GET assets（固定scope的assetId）。设置保存成功前不发布新状态，取消编辑不写入。订阅改变取消旧 generation，停用注销 API/卡片/调度并取消任务。

## 验证

从仓库根执行 `node tests/run.mjs plugin --plugin GameActivities --host-root <Host绝对路径>`。现役 runner 编译真实 SDK、类型检查/构建、发现固定 C# 用例，记录 TRX，并在隔离 asInvoker Test Host 验证目录、设置冲突/取消/重启和浏览器 mount/dispose。真实来源、桌面默认浏览器和人工视口分别验证；受控行为测试不能替代这些实际验证，未执行项记录为not_run。
