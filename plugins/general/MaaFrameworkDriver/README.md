# MaaFramework 框架直驱

读取本地 MaaFramework PI v2 项目及已保存配置，在 NexusPipeline 中运行任务。当前版本 0.2.3，需要兼容的 NexusPipeline 0.17.3，运行环境为 Windows 11 x64。

## 开始使用

1. 安装并启用插件，按提示重启宿主。
2. 新建 MaaFramework 脚本并选择完整的本地项目目录；支持 MXU、MFA、MFW-PyQt6/CFA 和 MaaPiCli 保存的配置。
3. 多个 interface 或来源实例时选择目标；仅在缺少信息时补齐控制器、资源、运行库及窗口/ADB 约束。
4. 使用宿主“保存”验证本地输入并执行初始化，清理确认后发布修订。初始化可能运行项目 pretask、Agent 或已映射的启动程序，不提交正式任务。

MXU 预任务按所选实例保存的启用状态、顺序和独立选项执行；未添加或已关闭的预任务不运行，也不进入正式任务队列。

MFA 支持独立实例文件及 `appsettings.json` 登记的旧式共享配置实例；按实例选择配置文件，保留任务选择和顺序，不继承其他实例的字段，不改写上游文件。外部启动动作和未支持的定时配置会明确阻断。

项目必须自带完整运行库和需要的 Python 环境。插件不下载运行库、不安装 Python 依赖、不修改系统 PATH。旧运行库绑定需重新保存，缺失或歧义会提示处理。

## 运行与来源同步

任务身份、顺序、禁用状态、次数和选项进入冻结计划。原生任务失败且清理确认后，宿主在总预算和最大尝试次数内续跑失败任务及尚未完成的后续任务，保留已经成功的任务。来源变化在空闲时发布新修订，不重放 pretask 或初始化；正在运行的计划保持不变，输入字节变化会阻止使用旧计划。

Maa 不提供自定义判断入口。历史显示框架任务结果及每次尝试；框架成功并不证明游戏奖励或其他业务成功。旧判断正文保留但不执行。驱动不反向写入上游 GUI 配置，也不自动迁移专项插件脚本。

Agent 和 pretask 执行项目代码，请使用可信项目。真实项目 Agent、游戏任务和奖励需独立验收；受控窗口测试不代表游戏资格。

[详细配置、限制与验证](https://github.com/FlappiBakuse/NexusPipeline-Plugins/blob/main/docs/frameworks/MAAFRAMEWORK_DRIVER.md)。

MFA 配置中未启用启动动作及断线启动重试的 `SoftwarePath` 可原样保留，不据此启动游戏；启用的 GUI 启动或重试动作仍明确阻断，需使用已审查的 Host 启动设置。
