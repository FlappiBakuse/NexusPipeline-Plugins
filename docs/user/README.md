# 安装与第一次使用

适用于 NexusPipeline 0.18.0 本地候选及与其配套的官方插件。可安装版本、来源和运行状态以 Host 插件页面为准；本文不提供尚未正式发布的下载渠道。

## 安装前准备

- 通用插件按需选择。专项插件需要你另外安装对应的自动化软件，并先用它保存正确的账号配置。
- 游戏、模拟器或上游程序应能独立正常工作。插件不会替你安装游戏、登录游戏账号或补全任意上游依赖。
- 在测试新客户端前备份已有实例和上游配置，使用独立开发实例；不要让旧、新客户端同时接管同一个配置目录。
- 若上游正在执行任务或编辑配置，先正常结束，再进行接管或配置编辑。

## 安装、启用和更新

1. 打开 Host 的插件页面，查看插件说明、版本、所需 Host 版本与来源。
2. 从已配置、可信的插件源选择需要的插件，按界面安装并启用。
3. 如界面要求重启，先结束正在运行的任务，再按提示重启。
4. 前往[插件选择表](../../README.md#选择插件)列出的入口。没有独立页面的 provider 插件，会出现在对应脚本目标或编辑区域。
5. 更新前查看变更说明；更新后先复核一个受影响的设置或任务。不要把 DLL 直接复制进正在运行的应用目录。

本地开发候选通过 Host 既有的受控安装入口使用。源码目录、任意 ZIP 或单个 DLL 都不自动成为可安装包；作者准备方式见[作者入门](../authors/README.md)。

## 第一次接入专项脚本

1. 在上游程序中完成账号、任务和运行目标设置，保存后退出编辑界面。
2. 在 Host 的脚本管理中添加脚本，选择对应专项类型和已经安装的目录。
3. 核对发现的程序、配置文件、账号或实例身份。目录中有多个候选时，根据真实账号选择；不要靠列表顺序猜测。
4. 建立账号与脚本的绑定，核对现有来源或已保存快照中的任务范围和启动目标。可以主动读取配置以检查或同步；目标流程中，来源已经明确且验证通过的首次运行会自动建立初始快照，不要求所有新绑定先手工导入。
5. 保存后先手动运行一次，确认历史中任务结果与上游实际动作一致，再创建或启用计划。

选择目录后自动发现；通用脚本首跑从有效现场建立初始快照。专项继续执行自身 preflight，按声明建立并核对账号快照。插件的额外前提见[八个专项](specialized.md)。

## 什么时候不要再次点运行

“正在运行”“结果待确认”和“失败”表达不同事情。结果待确认可能表示外部动作已发生但本地还没拿到确定结果；先打开该次记录查看、等待或使用已有的结果核对入口。特别是签到、领奖和消耗资源的任务，不应通过连续点运行来试探是否成功。

## 停用与卸载

先结束本插件相关的任务与编辑，再停用或卸载。保全账号配置与凭据；卸载界面的数据保留含义以当前版本说明为准，不把重新安装作为清空不明数据的办法。卸载插件后已有历史仍应可读，但插件能力本身不会继续提供。

## 当前操作与排障

专项发现、初始配置、日志与任务选择见[专项使用](specialized.md)，即时设置与页面入口见[通用插件](managed.md)，凭据与计划见[签到](game-checkin.md)。异常按[故障处理](troubleshooting.md)记录阶段与原操作身份。

已安装插件统一由 Host 的 `runtime/extensions` 管理。默认插件仅在新实例初始化时安装，应用更新与保留数据重装沿用原选择；完整目录被外部删除时由 Host 协调登记，配置与历史保留。日常安装和卸载使用插件中心。
