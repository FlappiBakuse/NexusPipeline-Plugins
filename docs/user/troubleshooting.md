# 插件故障处理

先确认问题属于安装、配置读取、任务执行、结果展示还是外部平台。每次只处理对应环节；保存原错误和操作时间，不反复清空数据、重装或重跑任务。

| 可见现象 | 先检查 | 下一步 |
|---|---|---|
| 插件已安装但没有独立页面 | 该插件是否本来就提供独立页面；是否启用并按要求重启 | 从[选择表](../../README.md#选择插件)进入对应表面；模拟器和专项通常嵌入目标/脚本编辑 |
| 提示版本或契约不匹配 | Host 与插件是否来自配套候选 | 使用明确配套的包；不要手改指纹或复制 DLL |
| 选择目录后没有配置 | 安装根、必需程序、已保存配置是否存在 | 使用实际读取入口；多候选时明确选择；保留未知文件 |
| 配置发现结果与刚选目录不同 | 是否有旧请求晚到，是否选了另一个目录 | 重新核对来源，不保存不相符结果；报告目录切换顺序与时间 |
| 编辑配置需要重新指定程序 | 是否为尚未对齐的原生编辑入口 | 核对已绑定上游，保留配置；本轮目标是恢复直接编辑绑定配置 |
| BAAH 正常退出但任务待核实 | 文件日志是否开启；是否为已知日志接线缺陷 | 保留日志与结果；等修复或用受支持版本，不强制改成功 |
| BAAH 文件日志修复预览失败 | 基线修复阻断问题 | 退出上游后在上游自身设置中启用，再重新读取；不要改摘要绕过 |
| OkNTE 只有启动器行为 | 该候选是否已修复日常入口 | 停用自动日程，核对版本及修复状态 |
| 签到网页登录空白/关闭 | 窗口是否真正打开、网络及平台状态、脱敏错误 | 取消本次登录并保留普通草稿；不要以真实签到作网络探针 |
| 签到或保存结果待确认 | 是否已经发起过同一操作 | 查询原结果；不创建新操作来重复外部效果 |
| 游戏活动一直显示旧数据 | 最后成功时间、刷新状态、是否仍在 60 秒间隔内 | 保留缓存，稍后刷新；订阅变化后旧响应不能覆盖新选择 |
| 壁纸上传失败 | 格式、大小、数量和总配额 | 使用一张有效图片复核；不连续重复上传同一未知结果 |
| 实时截图等待或不可用 | 当前任务是否已有正确目标、窗口/ADB 是否就绪 | 处理该目标；不要把其他任务旧画面当作当前成功 |
| 模拟器实例不明确 | 多安装、同名实例、端口冲突 | 选择准确安装与实例；不按名字批量结束进程 |
| Maa 项目能预览但不能运行 | 阻断诊断、控制方式、资源与程序映射 | 修正明确问题；预览成功不代表目标可执行 |

## 提交问题时附上什么

提供 Host 与插件版本、受影响插件、上游版本、具体操作顺序、脱敏错误、是否可重复，以及该次任务/操作的标识。画面问题可附只包含必要区域的截图。不要附账号凭据、完整 Cookie、Token、密码、短信验证码或含这些内容的原始网络记录。

运行中故障先结束该次运行，等待程序退出和配置恢复。无法确认恢复时保留原目录与日志；不要新开第二个客户端接管同一现场。当前操作入口见[操作与排障](README.md#当前操作与排障)。

## 开发人员的定位边界

用户报告提供症状，不能单靠截图推断根因。先用当前任务卡定位一次读、一次写或一个生命周期，代码批次完成后再按[统一定向验证](../developer/validation.md)采证。只扩大到能解释该失败的下一层；不要为了一个登录白屏重新验证所有 14 个插件。
