# 八个专项：接入已有自动化软件

先完成[第一次接入](README.md#第一次接入专项脚本)。专项负责识别所选配置、解释任务和日志，并通过 Host 管理执行；它们不包含上游软件。本文使用已锁定上游范围，更新上游版本后需重新核对支持情况。

## 共用操作与结果

- 在上游保存正确配置，再在 Host 选择对应根目录、账号/实例和现有配置。配置文件名相似时，以账号或实例身份核对。
- 编辑配置前结束正在使用它的程序。Host 对工作副本的修改完成后才发布；取消不应把编辑中的临时值留给上游。
- 未知或未覆盖任务应保持可见，不从列表中删掉它们来制造完整覆盖。存在无法安全判断的任务时，先查看诊断。
- “进程正常退出”不自动说明每项业务成功。日志缺失时保留待核实状态，不能只根据最终横幅猜成功。
- 重试只使用已证明允许的范围。普通入口接续与专项失败子集各有规则，不手工清空上游的日期、次数或进度来强行重跑。

## BAAH

**用途与前提：**接入蔚蓝档案爱丽丝助手。先安装受支持的 BAAH，保存需要使用的账号配置，并启用文件日志。源码研究范围为 BAAH2.5.1；具体文件身份见[上游锁](../../plugins/specialized/baah/upstream.json)。

**入口与操作：**在 Host 添加 BAAH 专项，选安装目录和目标配置；同时核对账号主配置及软件配置，读取任务后确认活动流水线、登录和收尾选择。

**第一次验证：**选择已有、可控的一次任务，查看 BAAH 实际生成的日志及 Host 中对应任务的结果。必要登录步骤属于新进程准备的一部分，不应因上一轮登录成功而被一概删去。

**常见失败：**缺少任务结果时检查本次文件日志及当前配置诊断。关闭文件日志时可先查看修复预览，再明确应用；保留其他字段与账号。也可正常退出上游后在其自身设置中开启文件日志并重新读取。缺失业务结果继续保持未知，排障见[故障处理](troubleshooting.md)。

**支持边界：**已选但未知的自定义任务可能含外部副作用，不会自动重放。配置编辑保留原任务、未知字段及进度。详细范围见[BAAH 项目参考](../projects/baah.md)。

## BetterGI

**用途与前提：**接入 BetterGI 的一条龙配置；上游先保存一条龙任务和游戏路径。当前研究范围为 0.66.0，[上游锁](../../plugins/specialized/bettergi/upstream.json)。

**入口与操作：**添加 BetterGI 专项，选择安装根及明确的一条龙配置；核对可选的 `User/config.json` 是否属于同一安装。确认任务名称、顺序和禁用状态，再保存账号绑定。

**第一次验证：**选一个已配置任务，检查任务组的开始、结束和实际结果，确认 Host 选择了正确配置；不要把一个任意脚本内部的成功文字当作整个一条龙完成。

**常见失败：**缺少日志、配置组来源不明或任务范围不完整时，先重新核对原配置和日志。重复名称需要结合保存身份，不能只按名称猜选。

**支持边界：**适配器识别内置任务及配置组的外层闭环；不会推断任意脚本内部效果，也不会重置额度、日期、次数或未知字段。参考[BetterGI](../projects/bettergi.md)。

## MaaEnd

**用途与前提：**接入终末地小助手现有配置。需要已经安装 MaaEnd；不需要额外安装通用 MaaFramework 框架直驱。研究范围为 v2.35.0，[上游锁](../../plugins/specialized/maaend/upstream.json)。

**入口与操作：**在上游先选好自动启动实例并保存；添加 MaaEnd 专项，读取目录中的实例与任务。自动实例必须能唯一匹配，不能让 Host 任意选第一个。

**第一次验证：**确认 Host 展示的实例就是上游选择的自动实例，运行后只检查这一个实例的任务结果。取消后确认上游停止，再继续编辑。

**常见失败：**未设置自动实例、重复 ID、接口资料缺失或不受支持的控制方式会阻断读取/运行。先修复上游配置并重新读取，不通过改成任意实例绕过。

**支持边界：**调用用户已安装的上游程序；专项包不附带 DLL、worker、原生运行时或浏览器编辑器。未知任务保留并标注范围。参考[MaaEnd](../projects/maaend.md)。

## MaaStellaSora

**用途与前提：**接入星塔助手的已有实例。研究范围为 v1.8.0，[上游锁](../../plugins/specialized/maas/upstream.json)；同样不要求通用 MaaFramework 插件。

**入口与操作：**先在上游保存账号实例，添加 `maas` 专项并选择对应配置。以 `config/instances` 中稳定的文件身份确认实例，不能只看显示名称。

**第一次验证：**读取后核对实例、任务和运行目标，执行一个受控任务；再取消一次编辑，确认没有把自动运行设置意外留在上游。

**常见失败：**配置指向不存在的实例、默认配置来源不明或日志不完整时，先核对真实来源。默认配置缺失时的来源选择属于该上游已存在格式，由插件按声明处理，不让用户随意改文件名。

**支持边界：**原生编辑仅修改已声明的准备/提交字段，取消恢复原字节；任务运行仍由上游完成。参考[MaaStellaSora](../projects/maas.md)。

## March7thAssistant

**用途与前提：**接入三月七小助手。研究范围为 v2026.10.16，[上游锁](../../plugins/specialized/march7th/upstream.json)；安装目录需包含对应 Launcher 与 Assistant。

**入口与操作：**添加 `march7th` 专项，读取并核对保存的 YAML 配置。配置编辑和实际执行的程序职责不同，应使用发现结果绑定的入口，不自行把两个 exe 替换成同一个。

**第一次验证：**确认选中的任务、父开关和子任务次数与上游一致。受控失败后的续跑应保留此前成功结果及原生计数，不从初始配置重新抹掉进度。

**常见失败：**目录缺入口、YAML 解析或资源绑定错误时，保留原文件并修正来源。最终横幅不能覆盖已经明确失败的子任务。

**支持边界：**编辑任务选择及已声明参数，保留原生计数、日期和进度；真实游戏行为另需对应环境。参考[March7th](../projects/march7th.md)。

## OkNTE

**用途与前提：**接入 ok-nte 的单账号日常任务。研究范围为 v1.4.21，[上游锁](../../plugins/specialized/oknte/upstream.json)。先在上游保存完整日常事项、顺序、互斥选择和游戏路径。

**入口与操作：**添加 `oknte` 专项，读取日常配置与日常专属参数；独立战斗、钓鱼或启动器页面的配置不属于这份日常列表。

**第一次验证：**观察确实进入“日常任务”，并按勾选事项执行；只看到启动器打开不算完成。如果仅打开启动器，暂停相关日程并检查该次任务选择与日志，见[故障处理](troubleshooting.md)。

**常见失败：**不完整或重复的日常列表、未知启用项、日志范围缺失会限制逐项重试。先在上游保存明确配置；不要借删除未知项改变原意。

**支持边界：**仅已知、选中、启用且明确失败的日常项可进入允许的重试范围；保留计数、日期、捕获档案及未知字段。参考[OkNTE](../projects/oknte.md)。

## OkWW

**用途与前提：**接入 ok-ww 的单账号日常。研究范围为 v3.7.12，[上游锁](../../plugins/specialized/okww/upstream.json)。先配置体力分支、附加事项和游戏路径。

**入口与操作：**添加 `okww` 专项，核对日常配置及已使用的附加配置。日常的隐含步骤没有独立开关时，界面不应虚构开关。

**第一次验证：**核对日常父任务与子项的真实结果。父流程返回成功而子项失败时仍应显示部分失败，不用再次整体重跑来尝试补齐。

**常见失败：**不受支持的 4C 模式、无界次数、未知附加项或缺日志时先调整上游的明确选择。启动参数不可照搬 OkNTE 的任务编号。

**支持边界：**仅符合该上游完整续跑规则的日常失败才允许原入口重试；开启 4C、部分成功或未知范围时，不自动重放资源消耗。参考[OkWW](../projects/okww.md)。

## ZzzOneDragon

**用途与前提：**接入绝区零一条龙的单一账号实例。研究范围为 v2.5.6，[上游锁](../../plugins/specialized/zzzonedragon/upstream.json)。先在上游配置目标账号和应用组。

**入口与操作：**添加 `zzzonedragon` 专项，选择 `config/<两位实例>/` 对应账号。确认任务组、账号和体力计划来自同一实例；当前 GUI 页签不能代替账号身份。

**第一次验证：**只运行选中的实例，查看组内任务顺序和实际结果，再核对历史仍属于该账号。配置隔离本身不能替你证明游戏已经登录正确账号。

**常见失败：**重复任务身份、未知启用项、旧格式未完成迁移或递归启用“一条龙”自身时，保留原配置并按诊断处理。不要把多实例参数拼在一起运行。

**支持边界：**旧保存格式可以只读发现，不据此伪造可写选择；体力进度、日期与计数由上游负责，部分成功和未知消耗不自动重放。参考[绝区零一条龙](../projects/zzzonedragon.md)。
