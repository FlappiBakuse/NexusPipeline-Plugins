## 维护规则

- 完成、失效或确认为既定契约的事项及时移出本台账，历史由 Git 与发行记录保留；不要长期累积已完成检查清单。
- 新条目先确认当前代码路径、测试和影响范围；区分“尚未运行”“已验证但受限”和“实现缺失”，不把 unknown 写成成功。
- 真实环境与新的 UAC 试验分别依据实际授权执行，既有隔离试验许可不自动扩展到其他现场。
- 修改公开协议、资源布局、诊断或运行语义时同步 Host 契约与两仓测试；同一正式插件版本的稳定包字节不可变。
- 文档与代码/测试冲突时先核对实际契约，不通过修改台账掩盖失败或扩大支持范围。具体作者与验证入口见[贡献指南](../CONTRIBUTING.md)和[文档门户](README.md)。
